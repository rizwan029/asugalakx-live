System design

Architecture Overview

Seven layers, from the browser to the blockchain. A planned design — shown as documentation, not a live system diagram.

Layer 1 — Client

Frontend
Next.js / React, Tailwind CSS

The presentation layer: pages, dashboards, charts, and the Academy experience. Static-first, accessible, and fast on low-bandwidth connections.

Layer 2

Services

Backend — Node.js with a dedicated API layer serving data, auth, and community features.

Layer 3

Storage

Database — PostgreSQL for relational data; Cache — Redis for low-latency reads and rate limiting.

Layer 4

Feeds

Data — Market APIs, News APIs, and Economic Calendar APIs, normalized into one internal feed.

Layer 5 — Intelligence

AI — seven specialized agents for signal discovery, verification, market structure, macro context, narratives, research, and community intelligence. In development

Layer 6

Layer 7

Security

How We Approach Security

A process, not a promise. These are the controls and workflows built into every release.

◈

Data Validation

Incoming market data is validated, normalized, and checked for anomalies before it reaches any display or model.

◉

API Security

Authenticated endpoints, rate limiting, and scoped keys. No secrets in client-side code, ever.

◊

Wallet Security

Non-custodial by design. Wallet connections are read-scoped; the platform never holds or moves user funds.

○

Access Control

Least-privilege access across services, environments, and team roles, reviewed on a regular cadence.

◌

Monitoring

Logging, alerting, and incident workflows for services and data pipelines, from staging through production.

◍

Contract Review Process

Any on-chain component follows a review pipeline: internal review, independent security review, then testnet — mainnet only after review milestones are met. Proposed

Release path: testnet → review → mainnet

Step 1

Testnet

New components deploy to test environments first, with public behavior documented for review.

Step 2

Review

Independent security reviews and internal audits of findings before any mainnet consideration.

Step 3

Mainnet

Graduated rollout with monitoring, rollback plans, and clear status communication.
